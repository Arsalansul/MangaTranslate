# manga-tl

Перевод текста на страницах манги и вебтунов с сохранением исходного стиля:
оригинал стирается, на его место встаёт переведённый текст тем же кеглем,
начертанием и выключкой.

## Как устроено

Три части с чётко разделёнными ролями:

| Часть | Роль | Где живёт |
|---|---|---|
| CV-контейнер | «глаза» — находит текст и распознаёт его | Docker, Linux, Python 3.11 |
| Хостовый мост | «руки» — стирает и верстает через Photoshop | Windows, системный Python, только stdlib |
| Модель | «голова» — переводит и принимает результат | Claude Code |

Разделение не случайное. Photoshop не умеет ни детект, ни OCR — значит
CV-часть нужна в любом случае. Зато он несравнимо лучше верстает: настоящий
текстовый движок с переносами и кернингом, Content-Aware Fill вместо
нейросетевого инпейнта, и на выходе PSD с живыми текстовыми слоями, которые
потом можно править руками.

Побочный выигрыш: самая тяжёлая для GPU часть — инпейнт — уходит в Photoshop,
и контейнеру остаются детект с OCR, которым хватает CPU. Поэтому отсутствие
CUDA (например, на AMD) перестаёт быть проблемой.

## Контракт

`container/app/schema.py` — единственная стабильная точка системы. Модели
детекта и OCR внутри контейнера меняются свободно, форма `Region` — нет:
на неё завязан скрипт, который стирает и верстает.

Обе стороны работают в пикселях от левого верхнего угла, поэтому координаты
переносятся в Photoshop без пересчёта (`rulerUnits = PIXELS`).

Ключевые поля:

- `bbox` — рамка текста впритык; `mask_poly` — контур **с запасом**, для стирания.
  Разделены намеренно: заливка впритык оставляет хвосты от глифов.
- `kind` — `bubble` / `caption` / `sfx`, определяет стратегию стирания.
- `on_art` — текст лежит на рисунке, а не на ровном фоне. Для таких
  Content-Aware Fill рискован и нужен просмотр глазами.
- `font_px`, `line_h_px`, `all_caps`, `fg` — снятый с оригинала стиль, чтобы
  перенести его на перевод.
- `translation` — заполняется на хосте; контейнер его не трогает.

## Запуск

Скачать веса детектора (94.7 МБ, релиз самого manga-image-translator):

```bash
curl -L -o container/models/comictextdetector.onnx https://github.com/zyddnys/manga-image-translator/releases/download/beta-0.2.1/comictextdetector.pt.onnx
```

Веса лежат отдельным томом, а не внутри образа: так пересборка не тащит
за собой сотню мегабайт. Если файла нет, контейнер молча откатывается на
`opencv-morph-v1` — посмотреть, какой детектор поднялся, можно в `/health`.

Поднять контейнер (каталог с главами монтируется только на чтение):

```bash
cd manga-tl && PAGES_HOST="E:/путь/к/главам" docker compose up -d
```

Проверить, что всё живо:

```bash
python host/bridge.py health
```

Сквозной прогон одной страницы:

```bash
python host/smoke.py
```

Photoshop должен быть установлен и запускаться — мост управляет им через COM.

## Состояние

Работает:

- сквозная связка контейнер → мост → Photoshop → PSD
- контракт и координаты переносятся без потерь, включая пути с кириллицей
- **детектор** `comic-text-detector-onnx-v2`. На вебтуне 3 региона вместо 20
  у морфологии, ложных срабатываний на рисунке ноль. На странице манги все
  13 реплик разошлись по своим балунам: ни склейки через границу панели, ни
  разрыва пузыря, `on_art` не соврал ни на одном балуне. ~10 с на CPU
- стирание по силуэту текста, а не прямоугольником
- вёрстка кириллицы: подбор кегля, центрирование, переносы
- PSD с живыми текстовыми слоями плюс PNG на проверку

Не работает:

- **SFX** модель не видит: на корейских мазках покрытие маски ровно ноль,
  это не вопрос порога. Звуки придётся отдавать отдельным проходом или
  оставлять как есть.
- **русский словарь переносов** не выставлен: `Language.RUSSIAN` в DOM
  ExtendScript отсутствует, нужен Action Manager.
- **шрифты** — в системе нет комикс-шрифтов с кириллицей, пока Arial.
- **OCR** на английской странице читает реплики узнаваемо, но с обычными для
  капслока комиксов подменами: `O`/`0`, `I`/`l`, `D`/`O`. Правится на этапе
  перевода, потому что контекст реплики известен, а Tesseract его не видит.
- **`kind`** для капшена всё ещё эвристика: `bubble` и `caption` различаются
  по вытянутости и яркости фона. На стирание не влияет, на выбор стиля — да.
- **мелкий мусор на мазках** — пара регионов в 20–40 px на штрихах туши.
  Отсекать порогом чернил нельзя: под тот же порог попадает настоящая
  реплика вроде «...!».

## Подводные камни

**Подгон кегля.** У абзацного текста лишнее просто скрывается, поэтому
`bounds` показал бы высоту рамки, а не текста, и переполнение прошло бы
молча. Замер идёт в заведомо высокой рамке, и только потом текст сажается
в настоящую.

**Обратные слэши.** В генерируемом ExtendScript не должно быть ни одного
литерального слэша — они теряются по дороге. Все спецсимволы строятся через
`String.fromCharCode(92)`. Проверка: в шаблонах `jsxgen.py` слэшей ноль.

**Вебтун не влезает в модель.** Вход у неё квадратный, 1024×1024, и лента
720×3700 сжимается до 199 px по ширине — текст пропадает физически, маска
даёт 0.3% пикселей. Длинные страницы режутся на квадратные тайлы с
перекрытием 20%, маски складываются по максимуму.

**Из трёх выходов модели нужны два, и каждый за своё.** `seg` (маска глифов)
даёт геометрию букв. `blk` (боксы блоков) даёт границу балуна — то, чего из
одной маски не вывести: без неё группировка склеивала текст соседних панелей
и рвала пузырь на широком межстрочье. Но `blk` обучали на пузырях манги, и на
вебтуне она молчит — нашла одну вотермарку и пропустила капшен, который маска
взяла целиком. Поэтому `blk` — подсказка, а не источник истины: строки, не
попавшие ни в один бокс, группируются геометрически, как раньше. Класс из
`blk` не используется вовсе — метки переворачиваются между прогоном по целой
странице и по тайлам. Карта строк `det` не нужна: постобработка DBNet
(pyclipper, shapely) ради того, что проекция уже чистой маски даёт точнее.

**Балуны, слипшиеся в один бокс.** Два перекрывающихся пузыря `blk` отдаёт
одним боксом, и OCR читает строки поперёк обоих — реплики перемешиваются
построчно, и перевести их уже нельзя. Блок режется по пустому вертикальному
коридору. Проверка нужна только для боксов: геометрическая группировка
требует перекрытия по X и двух колонок не породит, а текст с выключкой по
центру всегда сливается в один интервал, так что внутри колонки коридора
не бывает.

**Порядок операций.** Стирание идёт по фоновому слою и целиком до вёрстки —
иначе Content-Aware Fill возьмёт в расчёт уже созданные текстовые слои.
